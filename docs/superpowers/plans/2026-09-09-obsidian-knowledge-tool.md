# Obsidian Knowledge Tool Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build an unpublished plugin prototype that exposes governed Obsidian knowledge-management tools to MCP clients.

**Architecture:** A bundled TypeScript stdio MCP server calls Obsidian Local REST API through a focused client. Pure governance functions validate paths, metadata, lifecycle transitions, and content hashes before mutation. The plugin also ships a Skill that teaches agents the intended workflow.

**Tech Stack:** Node.js 20, TypeScript 5.9.3, `@modelcontextprotocol/sdk` 1.29.0, Zod 4.5.4, Vitest 3.2.7, esbuild 0.28.2, Undici 6.28.1.

## Global Constraints

- Do not modify `.claude-plugin/marketplace.json`.
- Do not push this branch or publish the plugin.
- Use `${CLAUDE_PLUGIN_ROOT}` for every bundled plugin path.
- Read the API key from sensitive plugin `userConfig`; never commit it.
- Do not expose generic overwrite, delete, Obsidian command, or attachment tools.
- Failed move operations must prefer duplicates over data loss.

### Task 3: Local REST API client

**Files:**
- Create: `plugins/obsidian-knowledge-tool/mcp/obsidian-knowledge-mcp/src/obsidian-client.ts`
- Create: `plugins/obsidian-knowledge-tool/mcp/obsidian-knowledge-mcp/tests/obsidian-client.test.ts`

**Interfaces:**
- Produces: `ObsidianClient.health()`, `search(query, limit)`, `read(path)`,
  `exists(path)`, `writeNew(path, content)`, and
  `moveSafely(source, destination, expectedHash)`.

- [ ] **Step 1: Write failing HTTP contract tests**

Use a local mock HTTP server to assert Bearer authentication, segment-safe URL
encoding, content types, search limits, destination conflict handling, hash
checks, write verification, and source trashing only after verification.

- [ ] **Step 2: Run the focused tests**

Run: `npm test -- tests/obsidian-client.test.ts`

Expected: FAIL because `ObsidianClient` does not exist.

- [ ] **Step 3: Implement the REST client**

Use Node `fetch`; use an HTTPS agent only when the configured URL is HTTPS and
`OBSIDIAN_ALLOW_INSECURE_TLS` is explicitly true. Map HTTP 401, 404, 409-like
destination conflicts, and transport failures to actionable typed errors.

- [ ] **Step 4: Implement safe move**

Read and hash source, reject stale hashes, check destination absence, PUT and
read-back verify destination, then call DELETE with `permanent=false`.

- [ ] **Step 5: Run tests**

Run: `npm test -- tests/obsidian-client.test.ts`

Expected: PASS.
